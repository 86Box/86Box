# HD44780 character LCD

A Hitachi HD44780 character LCD module, with the A00 (Japanese) character ROM,
is available on any machine:

| Setting | Where | Choices |
| --- | --- | --- |
| Enable | Settings → Other peripherals → **Character LCD (HD44780)** | |
| Size | Configure | 16x2 (default), 20x4, 40x2 |
| Panel | Configure | Yellow-green backlit, white on blue, grey reflective, amber on black |
| ISA I/O address | Configure | None (default), 300H, 308H, 310H, 318H |

There is one module per machine. It can be reached through the TS-3x00's LCD
port, an ISA I/O address, or a parallel port device, and all of them drive
the same module.

The glass is drawn in a window of its own. On a TS-3x00, which has an LCD
header, the window appears at power-up. Elsewhere it appears once something
writes to the LCD, so that a fitted but unused module stays out of the way. It
can be closed, and reopened from **View → Character LCD**.

## Interfaces

### ISA I/O ports

With an ISA I/O address set, the module takes two ports. Writes to the base
are instructions and reads return the busy flag (bit 7) and the address
counter. Base+1 is the data register. There is no standard address for an LCD
on the ISA bus, so the choices are in 300H–31FH, the range IBM set aside for
prototype cards. 300H is also the NE2000's default, so pick one of the others
if a network card is fitted.

### Parallel port

Choose **Character LCD (HD44780, Winamp wiring)** as the device on a parallel
port in Settings → Ports. That fits the module, with its Other peripherals
settings, without the checkbox there. The wiring is the one LCDproc's
`hd44780` driver (in its `winamp` connection type) and LCD Smartie use:

| LCD pin | Port pin | Register | Bit | Inverted by the port |
| --- | --- | --- | --- | --- |
| D0–D7 | 2–9 (D0–D7) | Data (base) | 0–7 | No |
| EN | 1 (nSTROBE) | Control (base+2) | 0 | Yes: EN is high while the bit is clear |
| R/W | 14 (nAUTOFD) | Control (base+2) | 1 | Yes: the bit set selects a write |
| RS | 16 (nINIT) | Control (base+2) | 2 | No: the bit set selects data |

So, with the port's bidirectional bit (5) clear, the control register values
are:

| Value | EN | R/W | RS |
| --- | --- | --- | --- |
| 03h | Low | Write | Instruction |
| 02h | High | Write | Instruction |
| 07h | Low | Write | Data |
| 06h | High | Write | Data |

The module latches a write on EN's falling edge, so put the byte on the data
port, then write 02h or 06h, then 03h or 07h. Its outputs are not wired back to
the port, so the busy flag and RAM can't be read this way, and software has to
wait instead. A printer's strobes come with nAUTOFD's bit clear, which makes
them reads, so printing to the port does not bring the window up.

### TS-3x00 LCD port

The TS-3100, TS-3200 and TS-3400 drive the module from their LCD header when it
is enabled under Other peripherals. Their BIOS puts the board's register block
at 70H. In LCD mode (bit 4 of the DIO control register, 7DH), 72H is the
instruction register and 73H is data, as on the ISA interface. In DIO mode the
header's pins are general I/O. The board leaves the LCD's RS and R/W pins to
their pull-ups, so a pulse on EN (73H bit 0) is a data read, which shows up on
pins 7–14 at 72H wherever they are inputs.

Writing 10h to 7DH also makes the DIO2 header's pins and the LCD port's pins
inputs. Write the value your board's software expects there if it uses them.

The BIOS only uses the LCD when no TS-9500 is fitted, so set Video to None to
see what it does with it.

## Implementation

`src/device/char_lcd.c` emulates the whole controller:

- the 8- and 4-bit interfaces;
- DDRAM and CGRAM, with the address counter wrapping between lines (27H to
  40H and 67H to 00H in 2-line mode);
- the entry modes, and cursor and display shifts;
- the underline and blinking cursors, with the blink at the 270 kHz
  oscillator's rate;
- 1- and 2-line modes and the 5x10 font's CGRAM layout;
- reads of RAM, with the data register's read-ahead, and of the busy flag and
  address counter;
- how long each instruction keeps the busy flag up.

Power-up leaves it as the internal reset does: cleared, 8-bit, 1-line, display
off. On 2-line glass in 1-line mode, the first line's unlit dots show as dark
blocks, as an uninitialised module's do.

A real HD44780 ignores what it is sent while its busy flag is up. The emulated
one takes it anyway, since software that times its writes by the bus can run
faster in an emulator than on the hardware it was written for.

`src/qt/qt_charlcd.cpp` draws the glass to a real module's proportions, with
the unlit dots faintly visible, the shadow each dark dot casts, the glow of
negative panels, and the liquid crystal's slow response.

## Verification

### By hand, with DEBUG

Each script sets the module up for 8 bits and 2 lines (38h), turns the display
on with a blinking cursor (0Fh), clears it (01h), sets the entry mode to
increment (06h), and writes "Hi" (48h, 69h). Where the interface can read, it
then reads the address counter, which should be 02, and the two characters
back from DDRAM. Type the lines at DEBUG's `-` prompt, or save them to a file
ending in `q` and run `DEBUG < file`.

ISA, with the address set to 300H:

```
o 300 38
o 300 0f
o 300 01
o 300 06
o 301 48
o 301 69
i 300
o 300 80
i 301
i 301
q
```

LPT1, at 378H:

```
o 378 38
o 37a 02
o 37a 03
o 378 0f
o 37a 02
o 37a 03
o 378 01
o 37a 02
o 37a 03
o 378 06
o 37a 02
o 37a 03
o 378 48
o 37a 06
o 37a 07
o 378 69
o 37a 06
o 37a 07
q
```

For LPT2 at 278H, use 278 and 27a.

TS-3x00, from DOS on the board:

```
o 7d 10
o 72 38
o 72 0f
o 72 01
o 72 06
o 73 48
o 73 69
i 72
o 72 80
i 73
i 73
q
```

The `i` lines should print 02, 48 and 69. The scripts don't wait for the busy
flag: the emulated module takes commands while it is up. On real hardware,
typing them is slow enough, but a script fed to DEBUG from a file on a fast
machine may need the clear (01h) to be followed by something else before the
next write.

### Smoke test

`tests/device/char_lcd_smoke.py` makes the same port writes through the
automation socket, so it needs a build with `-D AUTOMATION=ON`, on Linux or
macOS:

```sh
cmake -B build -D AUTOMATION=ON
cmake --build build
python3 tests/device/char_lcd_smoke.py --emulator build/src/86Box
```

It boots an IBM AT for the ISA and parallel port cases and a TS-3200 with no
video card for the TS-3x00 one, so it needs those machines' ROMs (`--rom-path`
if they aren't in 86Box's usual place; `--case` runs some of them only). Each
case runs the script above and checks the address counter and DDRAM. The
parallel port case reads them back through the same module's ISA port at
300H. A control case writes to the parallel port with nothing attached and
checks that nothing arrives.

This covers the interfaces and the controller's response to them. Neither
check looks at the drawn glass.

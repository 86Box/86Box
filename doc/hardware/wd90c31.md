# WD90C31 graphics cards

Two ISA16 devices are available in the Display settings:

| Device | Configuration name | Video memory |
| --- | --- | --- |
| Diamond SpeedStar 24X | `speedstar24x` | 1 MB |
| Paradise WD90C31A-LR | `wd90c31` | 256 KB, 512 KB or 1 MB |

## Supplied ROMs

Place the files under `video/wd90c31a/` in an 86Box ROM directory:

| Card | Filename | Dump size | SHA-256 |
| --- | --- | --- | --- |
| Diamond SpeedStar 24X | `wd90c31alrdiamondspeedstar24x1.BIN` | 32768 bytes | `253be992851e97f066360aa939e082ac489eaddeb4b1e31c75ccdf5f962be136` |
| Generic WD90C31A-LR | `BIOS.BIN` | 65536 bytes | `b0de6e86dad90c636b9a1943bfd4c2c2cde705c1232db3ae9097c98018439f7c` |

The supplied Diamond dumps are byte-for-byte identical. Only `wd90c31alrdiamondspeedstar24x1.BIN` is used; the duplicate is unnecessary. The Diamond BIOS identifies itself as SpeedStar 24X version 1.04.

The generic dump contains a valid 32 KB option ROM followed by 32 KB of `FF` padding. Both devices map the first 32 KB at C0000h. The supplied files are used unchanged; the ROM binaries are not part of the source patch.

## Implementation

`src/video/vid_paradise.c` extends the existing Paradise VGA implementation with WD90C31 identification, extended registers, board-specific clocks and RAMDAC handling. The generic device uses the existing SC11487-compatible DAC and ICS90C64A-903 clock model. These peripherals were selected for compatibility with the supplied BIOS; the exact components fitted to the original generic board have not been established from the ROM alone.

The Diamond device models the SS2410 identification/command sequence used by its BIOS and uses the ICD2061 programmable clock. Its tested high-color commands select RGB555 or RGB888 output.

`src/video/vid_wd90c31.c` implements the indexed registers at 23C0h–23C5h, planar and packed BitBLTs, all sixteen raster operations, forward/reverse copies, fills, patterns, transparency, masks, host transfers, quick start, destination updates, completion interrupts, and the hardware cursor. Register behavior is based on the [Western Digital WD90C31 data sheet, sections 7–10](https://www.bitsavers.org/components/westernDigital/_dataBooks/1992_SystemLogic_Imaging_Storage/18_WD90C31.pdf), with the supplied BIOS instruction streams used to check integration.

Video-to-video operations finish synchronously. Host transfers retain busy status until the transfer completes. Engine throughput, FIFO contention, and interrupt timing are not cycle accurate. Cursor inversion reconstructs an indexed color from the rendered RGB value; palette entries with identical RGB values can make that reconstruction ambiguous. SS2410 behavior beyond the commands exercised by this BIOS is not comprehensively modeled.

## Verification

With `BUILD_TESTING=ON`, build and run the isolated engine tests:

```sh
cmake --build build --target wd90c31_tests
ctest --test-dir build --output-on-failure -R '^Wd90c31\.'
```

These tests compile the real engine with I/O and interrupt adapters and cover register access, drawing, transfers, memory layout, cursor colors/clipping/interlace, and the Diamond BIOS text-scroll register stream.

The full-emulator smoke test needs NASM, Python 3, an SDL build of 86Box, and the supplied ROM directory:

```sh
python3 tests/video/wd90c31_bios_smoke.py \
    --emulator build/src/86Box --rom-dir /path/to/wd90c31a
```

It creates a temporary, synthetic AT system BIOS, runs the unmodified video option ROM, checks BIOS text scrolling and VGA memory, then verifies displayed dimensions and a rendered pixel. The scroll check verifies every character and attribute in all 25 rows, including the new blank row, both before entering graphics mode and after returning to text mode. This covers the BIOS's temporary chain-4 access used to seed the BitBLT blank-row pattern. It exercises the generic card at all three memory sizes and the Diamond at 1 MB. Extended modes checked are 640×480×256 (5Fh), 800×600×256 (5Ch), 1024×768×256 (60h), and 640×480×32768 (62h), subject to available memory. Diamond also exercises 800×600×32768 (63h) and 640×480×16777216 (72h).

This is BIOS and device-level coverage. Windows accelerator drivers and a complete guest OS workload have not yet been qualified.
